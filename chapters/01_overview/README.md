## 为生成图像建立风险治理清单

### 为什么做

面对一张生成图像，直接选择检测器或过滤器，往往会把“是否生成”“来源是否清楚”和“使用是否合规”混为一谈。本实践先从使用场景出发，将风险、证据、控制措施和责任人写成可复核清单，为后续章节选择技术建立依据。

### 实践目标（应交付什么）

- 为三种给定应用场景分别标注五类风险，可同时选择多个维度。
- 形成包含证据、控制措施、责任角色及复核状态的CSV清单。
- 指出信息不足的字段，并给出补充证据的方法。

### 完成后应掌握什么

- 区分风险判断与模型分数，理解同一图像在不同场景中具有不同后果。
- 把治理目标转成可以分工、留痕和复核的任务。
- 识别自动化清单的边界，避免把预填示例当成真实审核结论。

### 环境和输入

只需Python 3.10及标准库，不需要显卡、模型权重或外部账户。先阅读三个程序内置的教学场景，再在场景数据文件中补充自己的判断。

环境安装见[环境说明](../../docs/environment.md)。先从仓库根目录运行：

```powershell
python tools/check_environment.py --profile standard
python tools/run.py 01 --dry-run
```

### 操作步骤

1. 运行程序生成三行初始风险清单；这些字段仅是教学示例。
2. 检查广告、新闻插图和授权肖像三种用途，逐项填写证据缺口及复核人。
3. 选取一行修改其使用场景，比较原有控制措施是否仍然适用。

在环境确认后执行：

```powershell
python tools/run.py 01
```

核心程序：[lab.py](lab.py)。运行结果位于仓库根目录results/，每次运行日志与环境摘要位于results/runs/。

### 预期效果

得到risk_register.csv及计数摘要。三条初始记录共六次标注，覆盖真实性、来源、合规性、公平性和隐私五类维度；同一行允许出现多个风险。计数表示清单中的标注次数，不表示真实事故概率。

### 本地实测状态

本轮已在本机执行标准库程序，生成3条教学场景记录、6次风险标注，覆盖五类风险；三条记录的复核状态均为待核实。输出用于验证清单结构，不是对真实产品的风险评估。

### 结果分析与提交物

如果缺少来源、授权或用途信息，应标注待核实并指定补证动作。不要因为清单里没有某一风险，就把它解释为该风险不存在。
