## 生成第一张图像

### 为什么做

理解文生图流程，不能只记住文本编码器、去噪网络和解码器的名称。通过完成一次可记录的生成，并只改变提示中的颜色词，可以把抽象模块与可观察输出对应起来，也为后续鉴伪、水印和治理实验准备共同输入。

### 实践目标（应交付什么）

- 生成同一种子下的红杯和蓝杯两张图像，保存原始提示、采样参数与输出。
- 建立最小实验记录，写明模型、设备、精度、随机种子和软件版本。
- 比较颜色、背景、把手及杯内状态，区分预期变化与伴随变化。

### 完成后应掌握什么

- 将“提示词—条件编码—去噪—解码”的概念链与实际调用对应。
- 理解固定种子和单变量对照各控制什么，知道固定种子不等于局部编辑。
- 识别下载失败、显存不足和非有限数值等运行问题，避免把黑图当作有效样本。

### 环境和输入

生成环境采用Python 3.10、PyTorch 2.5.1与Diffusers 0.32.2等固定依赖；CUDA版PyTorch须与设备和驱动匹配，CPU使用对应CPU构建。按配套环境文档创建独立环境，安装后先检查版本与设备。首次运行需下载模型权重并遵守其使用条件。

环境安装见[环境说明](../../docs/environment.md)。先从仓库根目录运行：

```powershell
python tools/check_environment.py --profile generation
python tools/run.py 02 --dry-run
```

### 操作步骤

1. 检查环境和输出目录，保留本次环境清单。首次下载失败应先解决网络或模型访问问题。
2. 运行红杯和蓝杯对照，提示词只替换red与blue，其他参数保持一致。
3. 检查两张图及设置记录。再改种子重复一组，分别记录颜色是否符合提示以及其他元素的变化。

在环境确认后执行：

```powershell
python tools/run.py 02
```

核心程序：[lab.py](lab.py)。运行结果位于仓库根目录results/，每次运行日志与环境摘要位于results/runs/。

### 预期效果

得到两张512乘512图像、参数文件和运行日志。主体应与杯子提示相关，但构图、把手和杯内状态也可能一起变化。保存安全检查信号；黑图、异常和缺失图像要单列，不能当作正常生成结果。

### 本地实测状态

已有本机实测：GTX 1660 SUPER，PyTorch 2.5.1+cu121，float32，注意力切片与CPU卸载；种子2026、30步、引导强度7.5。两张图均成功生成。半精度尝试出现非有限值并返回黑图，作为失败记录保留。

### 结果分析与提交物

先核对运行是否有效，再比较图像。已有对照中颜色发生变化，把手与杯内状态也有差异，说明固定初始随机性没有保证只有颜色被修改。把观察写入逐项对照表，而非只给出“生成成功”。

提交本次输入说明、参数与环境记录、全部有效输出和失败记录，以及逐项观察表；引用随仓库历史实测时应明确为历史证据。
